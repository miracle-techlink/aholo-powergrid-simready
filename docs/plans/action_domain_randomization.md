# 动作适应性：物性区间、域随机化与独立验收

状态：开发方案，尚未实现域随机化训练。核查日期：2026-11-14。

## 已实现与缺口

已有 `physical_spec.py`、`category_priors.py`、`physical_authoring.py` 和独立 USD 审计，能够分别记录和写入物性。`physical_probe.py` 的协议明确为固定参数、固定初态；它验证物性是否影响仿真响应，不执行域随机化。

`cup_grasp.py` 以实际关节驱动和接触完成搬杯，放置阶段使用仿真真值位姿反馈；没有经过随机参数下的策略训练。`button.py` 根据实测接触力与行程更新按钮状态，但状态检测器不等于自适应控制器。`cafe_video.py` 中的巡逻是编排位姿回放，不能用质量或摩擦随机化宣称导航适应性提高。

GaussianProperty、NeRF2Physics、型号检索与真实运动参数辨识均未接入已评估的参数预测链。域随机化也不替代这些工作：辨识减少参数不确定性，随机化用于训练和检验动作对剩余不确定性的鲁棒性。

## 建议先完成搬杯闭环

| 环节 | 要做的工作 | 可验收的输出 |
|---|---|---|
| 参数分布 | 为杯质量、接触对摩擦、初始位姿、观测误差和控制延迟分别定义分布、范围和来源 | 冻结分布版本和每回合采样回执，未知区间标为探索假设 |
| USD 接入 | 每回合创建独立参数覆盖层；按对象绑定接触材料；质量与惯量保持一致 | 写入后重新读取数值；静摩擦不小于动摩擦；物性哈希绑定到该次轨迹 |
| 固定策略基线 | 当前搬杯控制不变，先在随机环境里执行 | 成功率、掉杯、滑移、碰撞、最大接触力、完成时间及全部失败轨迹 |
| 反馈控制 | 在原规划轨迹周围增加受限修正；基于接触/滑移调整夹持、提升速度、放置高度 | 闭环与固定策略在相同参数样本上的成对对照；限制夹持力和动作修正幅度 |
| 策略训练 | 如反馈规则仍不足，再训练残差策略或带历史状态的策略 | 固定训练预算、可复现 checkpoint、训练过程与验收环境隔离 |
| 独立测试 | 留出种子、留出参数组合及接近区间边界的困难组合 | 报告成功率和置信区间、最差参数组表现、力与碰撞代价，不只展示最佳录像 |

先用有限随机样本找出控制薄弱点，再确定训练规模。固定脚本在不同参数下多跑几遍属于鲁棒性测试；只有改变控制规则、优化控制参数或训练策略，才构成动作能力改进。训练可以不依赖强化学习，但必须有明确的优化对象与独立测试集。

## 随机化边界

- 质量、摩擦、刚度等环境参数通常在回合开始采样并保持固定；传感器噪声和有模型的延迟可以在运行中变化。不要每个物理步任意改质量或摩擦。
- 摩擦是接触对属性：杯体、夹爪和桌面各自材质及引擎组合规则都要记录。不能只随机杯体一个数字却忽略另一接触面。
- 质量、质心、惯量必须物理一致；几何尺度变化应同步更新碰撞、惯量、抓取点和规划输入。
- 静态桌椅无需随机一个不会参与动力学的“质量”。相关扰动应放在接触、放置面位置、碰撞几何及可观测位姿上。
- 用仿真真值物体位姿训练与用视觉估计训练须分别报告。已有搬杯放置反馈属于前者，不能直接称为实机可用视觉闭环。
- 不改变验收阈值来迁就训练结果，不把失败样本排除出成功率分母。训练和测试使用独立清单与输出目录。

## 按钮与移动控制的后续接入

按钮优先随机局部位置、按压方向、行程、刚度、阻尼及末端接触摩擦，保留同一套基于实测力与行程的成功判据。控制器需有对准、接触建立、限力按压和回撤反馈；一次预编排到位不代表对这些变化适应。

移动任务需要先接入真实动力学导航/运动控制，再考虑地面摩擦、坡度、轮或腿的执行器响应、状态估计误差和外扰。当前巡逻视频不进入这一类动作鲁棒性 benchmark。

## 没有实物时能说什么

可以报告“在所声明的仿真参数分布及留出组合上，动作成功率和接触代价如何变化”。不能报告真实参数已辨识，或真实机器人成功率已提高。以后有真实状态—动作轨迹时，再估计参数后验并收窄随机化范围。

研究依据：[Dynamics Randomization, ICRA 2018](https://arxiv.org/abs/1710.06537) 展示了训练时随机化动力学对机械臂推物迁移的作用；[BayesSim, RSS 2019](https://arxiv.org/abs/1906.01728) 使用真实轨迹推断仿真参数后验，并据此构造随机化分布。这些是方法参考，不是本项目已完成的实验。
