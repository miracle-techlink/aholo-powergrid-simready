### 仓库支撑层：配置、部署、示例和检查如何服务运行代码

安装边界由 `pyproject.toml` 定义：wheel 只收录 `src/simready`，默认依赖为空，采集、Aholo、仿真、评测和报告分别声明可选依赖。命令入口是 `simready.cli:main`，旧命令由 `compat_cli` 转发；CLI 不在解析帮助时启动模型或 Isaac。USD SDK 和 Isaac 来自显式选定的运行环境。源码仓库中的部署、示例和历史实验不因安装 wheel 自动成为运行时模块。

| 组成 | 构造与调用关系 | 使用与扩展责任 |
|---|---|---|
| `configs/` | 架构依赖规则、质量协议、资产一致性协议、修复能力目录 | 规则须与实现和版本一致；能力目录不能替代可执行插件注册表 |
| `deploy/isaac/` | Dockerfile 的 render 阶段装渲染依赖，physics 阶段加 Isaac Lab、策略运行库和 SDK 依赖修补；启动器由 `execution` 构造命令 | 使用者单独取得 SDK/镜像与资产；源码挂载位置、缓存和 GPU 显式配置 |
| `examples/new_video`、`scenes` | 声明场景、对象、bundle 和任务规格，作为入口参数 | 新输入需校准坐标、尺度和任务；复制示例不继承旧场景成绩 |
| 其他 `examples/` | 机器人绑定、合成修复循环、评测夹具、DAG 与性能实验 | 演示合同如何组合；合成结果不等于真实场景泛化 |
| `tests/`、CI | 领域测试、错误输入、恢复、引用闭包与端口检查；CI 在 Python 3.10/3.12 上检查、构包和运行 CPU 测试 | GPU 物理、视觉与任务证据另行保存，不由 CPU 通过推导 |
| `scripts/`、`docs/` | 架构与 AST 检查、性能记录、图表及 PDF 构建；保存说明、协议和实验凭据 | 报告从固定证据生成，不启动重建或更新实验数值 |
| `legacy/` | 历史 VGGT/gsplat、Gaussian 修复、场景评测与活动脚本 | 当前包禁止导入；迁移需补齐版本、I/O、资源、失败和独立验证合同 |

`scripts/check_architecture.py` 只读解析 AST，核对十个领域、允许依赖的无环性、禁止导入来源、`__main__.py` 入口长度约束及八个公共函数的注解与职责说明。规则来自 `configs/architecture/module_boundaries.json`，因此新增领域或跨域依赖必须同时更新设计与检查。`scripts/audit_source.py` 则枚举源码摘要、语法和顶层定义；它明确不认证集成执行，不将“可以编译”写成“任务通过”。

当前部署是可复用的本地/远端进程与容器组合。资源池、文件锁、缓存和回执有各自作用域，尚非跨主机集群控制面。新增场景首先扩展来源和场景合同；新增机器人扩展端口绑定与具体策略；新增修复算法扩展可信插件和独立评测；新增后端扩展启动、状态回执与失败恢复。每种扩展都应沿自己的接口进入，避免把场景专用路径或模型权限塞进 CLI。
