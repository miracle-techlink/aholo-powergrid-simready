# 变电站三轮工作流：15 分钟目标与优化账本

目标：把原 55 分 50.67 秒工程窗口中的三次独立物理任务、三次完整录制、资产处理和验收编排成可复跑流程，目标墙钟不超过 900 秒。当前**尚未达标**。不能把单次交付、三轮实验和优化开发耗时混为一谈。

本地基准保持：已有 Aholo 场景、Lite3 + Z1、2 ms 物理步长、24/8 求解迭代、714 帧、1920×1080、25 fps、原有物理审计和视频质量界限。新视频的云端重建另计；本轮没有新提交付费 Aholo 任务。

优化已于 2026-11-13 按用户要求暂停，当前转入代码封装与发布。最后一次三轮编排在首轮物理回放等价性检查失败后停止，耗时 478.97 秒；这不是三轮完整 E2E。

## 目标预算，不是实测预测

| 工作 | 目标关键路径预算 |
|---|---:|
| 资产处理与三个候选观测 | 80 秒 |
| 三次独立物理执行 | 240 秒 |
| 三次完整录制 | 480 秒 |
| 独立物理及逐帧视频验收 | 60 秒 |
| 报告、清单、打包 | 20 秒 |
| 调度与余量 | 20 秒 |
| 合计 | 900 秒 |

这是用于暴露差距的预算，尚未测得上述速度。三次物理/录制预算需要吞吐提升；单卡多进程并不自动等于多卡加速。原工程窗口中未独立计时的分析、排错、写报告时间也不能全部写成“已消除的等待”。

## 本轮实现

- `examples/deployment_profiling/runtime_variants.py`：对冻结的外部部署做显式、有限的候选变换；源代码锚点不符立即拒绝，保留原脚本。
- `execution.worker_groups`：父调度器持有一个 GPU 租约，最多三个直接子进程共享只读、不可修改的内存文件凭据；核对父 PID、进程启动时间与锁身份，不删除其他终端的锁。单 worker、进程失败和外国锁测试已覆盖。原 desktop / streaming 进程仍存在，不能称为独占 GPU。
- `execution.remote_polling`、`execution.process_supervision`：已有云端作业的有限退避、追加事件日志、心跳、总超时、重启恢复。只重读已有作业，禁止因网络故障重新提交收费任务。
- `ingestion.aholo_reconstruction`：公开入口；旧 `legacy/aholo_reconstruction/submit_panel.py` 仅兼容转发。签名下载不携带 API 会话头；已校验资产可复用，失败不会丢失前面的下载收据。

并发子进程仍然各自计算和生成输出。没有复用一次物理轨迹冒充三次物理计算，也没有拷贝视频冒充新录制。未通过验收的候选不会覆盖交付产物。

## 失败也进入工程记忆

1. 过早关闭视口会影响起始帧；保留前 16 帧渲染历史后，完整视频首个样本通过。
2. 不能在已经启动的 Hydra 渲染流程里随意切换多时钟设置；候选会停滞。启动阶段配置作为不同候选另测。
3. 相同 GB10 上的三个渲染进程会争用资源，短片收益有限且观察到画质失稳。默认不启用此配方。
4. Isaac Python 3.12 构建不导出 `fcntl.F_SEAL_*`，但内核支持 Linux UAPI；凭据校验使用相应 UAPI 常数，保留最初失败记录。
5. CPU 接触读数为零已定位到值得核查的配置：当前 IsaacLab 默认关闭 contact processing，GPU 和 CPU 路径可能表现不同。尚未完成修复和新后端验收，不把猜测写成已解决。
6. 物理快照必须在物理步进前后、RGB-D 采集前后失效；PyTorch 的版本号不能代表 PhysX/Warp 原地写入。
7. 新增独立下游检查：把 CUDA SAM 的标签交给原环境构建器，14 个 prim、173 项属性和 31 组关系均与 CPU 基准精确一致（资产路径按实际文件解析）。这是下游环境资产的等价证据，原 mask 逐位门槛的失败记录仍保留；没有泛化到其他输入。
8. 候选发现账本与正式 `PerformanceMemory` 晋升分开：本轮未把探索样本伪装成已满足两次重复的可复用成功配方。

## Aholo 恢复入口

```bash
pip install -e '.[aholo]'
simready ingestion aholo \
  --video /absolute/path/input.mp4 \
  --out /absolute/path/job_directory \
  --client /absolute/path/trusted_scene_recon.py \
  --poll-timeout 900 --supervise --max-attempts 3
```

已有 `receipt.json` 时只恢复其中的 `world_id`，并核对原视频哈希。只有首次明确运行此提交入口且没有旧收据/提交意图时才提交新任务。若已有 `submit_intent.json` 但没有收据，阻止自动再次收费，需找回服务端收据。

瞬时 SSL EOF、连接中断、超时、429、5xx 状态查询进入有限退避；401/403 等永久错误不重试。`TIMEOUT`、`REJECTED` 等服务端终态立即停止。`poll_events.jsonl` 追加记录状态，`heartbeat.json` 保存最近一次观察；不记录鉴权头、签名 URL 或响应全文。监督器保留各次 stdout/stderr，并用同一总截止时间终止自己的超时进程组。

已做故障注入测试：两次 SSL EOF 后恢复同一作业、SIGKILL 后恢复同一收据、服务端失败终态不重试、全局超时不重置、已验证下载不重复。另已对真实已完成作业进行只读恢复检查：0.419 秒、恰好一次 GET、原 PLY/SPZ 校验一致，HTTP 适配器明确禁止 POST 和上传。没有新云端重建，不能把该耗时当作重建 E2E。
