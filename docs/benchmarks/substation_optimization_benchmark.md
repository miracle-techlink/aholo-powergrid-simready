# 变电站 Infra / Kernel 优化基准与实验账本

基准 ID：`SUBSTATION-GB10-20261112-v1`
建立日期：2026-11-12。状态：**历史基准保留；已追加 GPU profiling 和首轮 RSI 候选实测，尚无通过全部门槛的新生产配置。**
用途：固定一次场景复跑的工作量、耗时和质量证据，后续按实验 ID 逐项优化，保留失败、回退及成本。

可以优化基础设施，也可以重写部分计算逻辑。先定位 CPU/GPU 关键路径，再选择批处理、减少同步、循环重构或自定义 CUDA kernel。现有 `sim.step` / RTX 调用的 host 时间不能整体当作可融合的张量算子时间。

## 7. 测量协议：三种口径不得混算

| 口径 | 定义 | 允许的结论 |
|---|---|---|
| Fresh local replay | 冻结 Aholo/已审核输入；相关资产重新生成；新物理/审计/全片录制；任务缓存关闭 | 相同本地工作量的执行速度 |
| Warm incremental | 声明命中的不变资产、模型驻留和实际重跑范围；仍保留要求的新验证 | 同输入/局部修改的增量延迟；不称为新视频重建提速 |
| Engineering window | 请求到明确结束事件，含工程、工具、队列、实验和报告 | Agent 工作流程成本；不能当作 GPU kernel 时间 |

1. **一次只变一个因素。** 保存候选 diff、代码版本、环境与协议哈希；控制组和候选使用新输出目录。原始基准目录禁止覆盖。
2. **先定位，再做完整验证。** 纯函数先用冻结状态张量/接触矩阵做小基准；物理候选随后必须跑完整接触任务。渲染 canary 需覆盖导航、相机切换、接触和回撤。
3. **注意现有 `--frames` 陷阱。** 该模式每个选定帧使用 16 子帧并重复预热，与完整录制的后续每帧 2 子帧不同。可以用于检查画面，不能用其每帧耗时线性推算 714 帧。后续若新增片段性能模式，应显式固定子帧/预热协议，并将预热成本单列。
4. **重型 profiler 与性能评分分开。** trace 用于归因；正常墙钟比较关闭 Nsight Compute/重型 trace。没有必要为每个小改动都重新做三条完整 profiling 视频。
5. **最终性能比较做配对复测。** 通过功能 canary 后，对目标阶段至少做 3 对控制/候选，交替或随机顺序，报告全部样本、median、min/max 与每对差值；只有 3 对不宣称可靠 p95。完整管线复跑用于确认局部优化没有转移开销。
6. **记录资源与并发。** 采集 GPU UUID、驱动、利用率/频率、统一内存、CPU、同卡其他进程及工作负载身份。无法得到字段时保留未知；不要把 32 GiB 调度预算写成峰值显存。当前租约只约束遵守相同协议的任务。
7. **失败照常计费。** 每次 attempt 单独保存日志、已用时间、退出状态；重试用新目录。墙钟按区间并集/关键路径核算，队列和并行工作不重复相加。

## 8. 工具与算子级归因

文档建立时本机发现：Nsight Systems `2025.3.2`、Nsight Compute `2025.3.1`。这里只确认工具可执行，**尚未确认 GB10 上本场景的 capture、计数器权限、API 覆盖和输出是否完整**。

- 用 Nsight Systems/CPU trace 先判断关键路径是 kernel、内存复制、同步、引擎调度、Python/NumPy 还是 I/O。
- 对已确认的 CUDA 热 kernel，再用 Nsight Compute 获取带宽、占用率等数据；NVTX 区间必须对应明确的阶段与帧/物理步。
- RTX 图形路径和 PhysX 内部实现不是都能当成自定义 CUDA 算子替换。Nsight Compute 面向 CUDA kernel；图形路径需要该平台支持的图形/API 时间线工具。未捕获到事件不等于该部分耗时为 0。[NVIDIA kernel profiling 工作流](https://docs.nvidia.com/nsight-compute/NsightCompute/index.html)
- 外部 C++/CUDA 调用可以有自定义算子封装，但封装本身不代表内部引擎已被融合或加速。[PyTorch 自定义算子](https://docs.pytorch.org/tutorials/advanced/cpp_custom_ops.html)

阶段层建议新增互斥计时：scene load、sensor acquisition、state readback、control calculation、contact statistics、physics step、USD pose update、render wait、encode、audit、artifact verification；同时保留父子 span。并行 trace 按关键路径分析，不把所有 kernel duration 相加当端到端墙钟。

## 9. 正确性与性能晋升门槛

### 9.1 当前事实与默认约束

- A/B/C 的实测轨迹数组完全一致，三轮独立物理审计均 20/20。基础设施、缓存、循环不变量重构优先以**精确轨迹等价**作为门槛。
- 若浮点计算顺序改变导致精确比较失败，候选暂不晋升；应另建数值等价协议，在测试候选之前冻结容差、任务成功率/接触/轨迹要求，不能根据失败结果反向放宽。
- 物理步长、求解器参数、控制/传感器采样频率、事件判据、物理时间、目标按钮和意外接触检测保持固定；根位置、按钮位姿不得通过写入来替代真实动作。
- 保留 121 个按钮、49 个旋钮及依赖合同。原 USD 属性比较容差 `1e-12` 对应其原比较范围，不能擅自当作仿真动力学的通用容差。
- 视频完整 714 帧、25fps、1080p，完整解码；RGB 与轨迹/事件时间对应、相机轨迹和质感要求保持一致。

### 9.2 渲染误差和源保真
